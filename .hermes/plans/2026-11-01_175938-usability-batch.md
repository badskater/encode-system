# Usability Batch Implementation Plan (v1.22.0)

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Eleven usability additions that remove day-to-day friction from operating the encode farm: scan-now trigger, terminal-job delete + bulk extensions, node online/offline alerts, publish platform picker in the UI, `encodectl` CLI, backup restore, shipped Grafana dashboard, viewer role + user CRUD, flow duplicate, in-UI update check.

**Architecture:** All backend work follows the existing patterns in `backend/internal/api` (net/http mux `METHOD /path` routes, `withAdmin` middleware, single-row JSON Settings blob = no migrations needed, `s.audit(...)` on every mutation). Frontend follows the existing dark ops-console design system in `frontend/src/styles.css` (violet accent `--accent`, Inter + JetBrains Mono, panel/elevated surfaces) — new UI must reuse existing component patterns (cards on Settings, dialogs, table row actions), NOT invent a new visual language (per frontend-design skill: check brand context first, use existing palette).

**Tech Stack:** Go 1.27 stdlib (backend), React+TS+Vite+Vitest (frontend), existing `internal/notify` Discord webhook, existing Prometheus text endpoint.

**Branch:** `feat/usability-batch` off `main`. Single PR → squash merge → tag `v1.22.0`.

4b. **Backup restore.** `POST /api/backup/{name}/restore`.
- Guards: name must exist in the backup dir and match the active backend's extension (`.db` SQLite / `.dump` PG); 409 if any job is `running` or `pending` (message tells operator to cancel/drain first); 409 on unknown name.
- SQLite path: copy current `/data/encode.db` → `encode.db.pre-restore-<ts>` (sibling of existing snapshot conventions), then atomically replace `encode.db` with the backup copy (copy to temp + rename; keep shares-key file untouched). Then log `restore complete, restarting` and `os.Exit(0)` in a goroutine after flushing the HTTP response — Docker restart policy brings it back on the restored DB. Response `200 {"restored":true,"restart":true}`. Document the restart in the handler comment + Operations.md runbook note (Task 6 docs).
- PG path: replay the JSON-lines dump inside a transaction: TRUNCATE all `pgBackupTables` in REVERSE order CASCADE-free (plain TRUNCATE, FK order reversed), insert rows per table (JSON row → column list from the record's keys, parameterized), then setval per BIGSERIAL table (reuse pgimport's `::regclass` pattern). No restart needed (pool sees new data); response `200 {"restored":true,"restart":false}`. Shares key file untouched (ciphertext parity guaranteed by dump format).
- Audit `backup.restore` BEFORE the swap (so it lands in the pre-restore snapshot at least; note in comment that the restored DB carries its own history).
- Tests: SQLite restore via temp data dir (seed DB, backup, mutate, restore, verify old rows back, verify pre-restore snapshot exists); PG restore only under `ENCODE_TEST_PG_DSN` contract-style test (dump → mutate → restore → compare); guard tests (pending job → 409, wrong extension → 400/409).

4c. **Update check.** `GET /api/updates/check` (any user): reads optional `ENCODE_GITHUB_TOKEN` env; GETs `https://api.github.com/repos/badskater/encode-system/releases/latest` (10s timeout, `Accept: application/vnd.github+json`, UA header); returns `{"current": Version, "latest": <tag>, "update_available": bool, "release_url": html_url}`; on any failure → 502 with `{"error": "update check failed: ..."}`. Tag compare: strip leading `v` from both, semver-ish string compare (equal-length numeric dot segments; fallback string !=). Repo owner/name from env override `ENCODE_GITHUB_REPO` (default `badskater/encode-system`) for testability. Unit test with `httptest` GitHub stub (set env to stub URL via a third env `ENCODE_GITHUB_API` override — document as test-only).
- Also surface `version` in `/api/health` response if not already present (additive field; check first).

## Risks / notes

- **server.go is touched by Tasks 1, 4, 5(none)** — waves serialize this; within a wave only one owner has backend-internal write access.
- **SQLite restore's `os.Exit(0)`** relies on Docker restart policy; documented, and only fires after the HTTP response flushes. HA+SQLite is not a supported combo (SQLite = single instance), so no split-brain concern.
- **Viewer role flips many route wrappers** — mechanical but broad; the 403 matrix test is the guard.
- Node-alert state is in-memory per replica (leader-gated) — after failover the new leader seeds silently; worst case one missed transition. Acceptable, documented.
- Update check requires `ENCODE_GITHUB_TOKEN` on the controller for the private repo; without it the endpoint 502s gracefully and the UI shows "check failed".
