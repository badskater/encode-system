# REPO_CONVENTIONS.md

Stack- and environment-specific rules for `encode-system`. Supplements `AGENTS.md`.

## Domain

Distributed anime encoding farm. Terminology used everywhere:

- **Controller** — Go HTTP service in a Linux container. Owns the job queue, node registry, flow definitions, and the UI API. Mounts the NFS shares read/write to detect new episode material.
- **Node / Worker** — Windows Server 2025 machine with an Nvidia GPU running the hybrid agent.
- **Agent** — `encode-agent.exe`: Go binary (service plumbing, heartbeat, job execution, auto-update, reboot enforcement) + PowerShell (`EncodeLib.ps1`) for encode steps.
- **Job** — one episode encode: a rendered PowerShell script executed on one node, one job per node at a time.
- **Flow** — an ordered list of named step templates (index, audio, encode, mux, release-copy, keyframes) with parameters. Rendered into the job's PowerShell script.
- **Episode folder** — `scripts/<Series>/Ep NN/` on the NFS share; contains source media + `1080.avs` / `1080.vpy` filter scripts authored by hand.

## Layout rules

- Backend Go module lives in `backend/`; agent and controller share one module, built from `cmd/controller` and `cmd/agent`.
- PowerShell library lives in `powershell/` and is pushed to nodes by the agent's auto-update; never hand-edit copies on nodes.
- Ansible in `infra/ansible/` (chosen over Terraform for this project — user decision). No secrets in the repo: `inventory` and `group_vars/secrets.yml` stay local and gitignored.
- Frontend in `frontend/` (Vite + React + TypeScript). API client generated by hand under `src/api/`.

## Encoding specifics

- Audio pipeline: `eac3to` → 16-bit WAV → `opusenc` → `.opus`. No FLAC
  anywhere in new code. Track selection: fixed index (`audio`/`audio_branch`)
  or MediaInfo language priority (`audio_lang`, default `jpn,eng`); the mux
  step reads the `audio.json` sidecar for the track language.
- Video pipeline: `DGIndexNV` → `.dgi`, then `x265_x64` (the fork with
  `--aq-strength-edge` etc.) reading the `.avs`/`.vpy` directly, 10-bit
  in/out. 4K uses `encode_4k` (CTU 64) with `2160.avs`/`2160.vpy` scripts;
  HDR sources get bt2020/PQ signaling via the `hdr.json` sidecar written by
  the separate `hdr_probe` step (fork-exact spellings: `smpte2084`,
  `bt2020nc`). Dolby Vision: `dovi_tool extract-rpu` on the source, x265
  profile 8.1 with `--dolby-vision-rpu` (needs dovi_tool.exe in C:\bin).
- Mux: `mkvmerge` with the standard track language/default flags from the
  legacy batch script; audio language comes from `audio.json` when present.
- Keyframes: `ffmpeg` → y4m pipe → `SCXvid` → `<Series> - NN Keyframes.txt`, only when the flow includes the keyframes step.
- Binaries live in `C:\bin` on nodes (moved from `E:\Encodes\bin`). Encode
  working dirs: `C:\Encodes\scripts` and `C:\Encodes\ReleaseFolders` — both
  NFS shares mounted by the Windows NFS client. Series folders are created
  via `POST /api/series` (UI: Series → Create series): `Ep 01…NN` on the
  scripts share + `[Group] <Name> - Raws [Tag]` on the release share.

## Conventions

- Commit prefixes: `feat:`, `fix:`, `docs:`, `refactor:`, `test:`, `chore:`.
- Go: `gofmt`, no exported globals, context on every handler. Structured logs via `log/slog`.
- PowerShell: `Set-StrictMode -Version Latest`, `$ErrorActionPreference = 'Stop'`, functions not positional scripts, exit codes meaningful (agent reads `$LASTEXITCODE` and process exit).
- All paths inside rendered scripts quoted; episode folder names can contain spaces and unicode.
- Tests: Go `testing` stdlib only (no testify). Frontend: vitest + testing-library.
- Never commit `.env`, `inventory`, `secrets.yml`, tokens, or Windows credentials.
